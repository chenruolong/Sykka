# Sykka 竞品情报月报规范

月报是阶段性判断层：回答过去一个完整自然月竞争格局发生了什么变化、证据是否改变判断、Sykka 应验证或采取什么行动。[Tracker](../intelligence-tracker.md) 是证据 / 长期记忆层：保存永久事件 ID、证据演进、当前判断和当前观察重点。月报不拼接日报，Tracker 不存放月报全文、日报全文或周维护日志。

## 周期与文件

- 时区：Asia/Shanghai。报告期为过去完整自然月，从当月 1 日 00:00 至下月 1 日 00:00（不含）；例如 2026-10-01 月结生成 2026 年 9 月报告。
- 路径：`competitors/monthly/YYYY-MM.md`，月份指被总结月份，不是生成月份；本 README 不代表定时任务已配置。
- 文件头记录报告期、生成日期、证据截止时间、状态（初稿 / 已月结 / 已修订）、输入覆盖及缺口。缺失日报或数据明确标注，不把部分月份称为完整覆盖。
- 区分事件发生日期、首次发现日期和证据获取日期。跨月事件沿用 ID；截止后新增材料标为期后补充，不冒充报告期内变化。

## 输入来源

1. 过去完整自然月的日报：发现 NEW / UPDATE 和线索，追溯原始来源；标明实际可读取日期及缺失区间。
2. 周五维护后的最新 Tracker：记录所用提交链接及复核日期；如尚未完成周更，注明并补核相关事件。
3. 全部 Active / Closed Signals：复盘本月进展、反证、关闭及重开，不仅统计仍活跃的事件。
4. 上月月报的 Next Month Watchlist（即报告月份的观察清单）：逐项检验结果。首次运行没有上月月报时写“无历史基线”，不得事后补造。
5. 事件原始来源、用户反馈和实际取得的数据：注明来源、日期、国家 / 平台 / 样本、统计口径及限制；不可访问或未取得的数据写待确认。

优先使用月末截止前的证据；若最新 Tracker 含期后更新，通过 Timeline 和历史提交还原期末状态。新闻转载不算独立证据，官方声明不等于实际效果，用户投诉不直接证明故障规模或原因。

## 固定月报结构

### Executive Summary

用 3–5 条概括最影响决策的变化及其证据强度，说明整体判断相较上月维持、加强、减弱或改变，以及主要不确定性。无实质变化就明确说明，不凑趋势。

### RedotPay

本月关键 NEW / UPDATE、相较上月的变化、证据支持的事实、推测和待验证假设；关联事件 ID 与来源，说明对竞争判断的影响。

### KAST

沿用相同结构，关注产品、市场、增长、商业化及可验证结果；促销规则与实际消费、留存效果分别记录。

### Industry

仅纳入对 Sykka 有明确意义的行业及雷达竞品变化；说明案例适用范围，不用单个事件推导全行业趋势。

### VOC/User Experience

按用户问题主题组织，注明来源、观察期、国家 / 平台、样本与重复处理方法；区分个案、重复出现的信号与已确认问题。无可靠样本则报告覆盖缺口，不虚构问题频率或用户占比。

### Implications for Sykka

将证据连接到产品、市场、增长或商业化决策：建议验证 / 行动、理由、预期观察指标及触发条件。Sykka 当前能力需有带日期的依据，未知标待确认。复盘报告月份 Watchlist 各项的结果、未解决原因及继续 / 结束跟踪决定。

### Next Month Watchlist

标题下明确目标月份 `YYYY-MM`。每项包含 RD / KA / IND 事件 ID（可多个）、待验证问题、检查来源、复查日期或触发条件及其决策意义；新线索尚未入库时标“待分配 ID”。保持少量重点，供次月日报优先核查，并同步至 Tracker 的 Monthly Watchlist。

## NEW / UPDATE 追溯

- 月报每条关键事件标注 `NEW` 或 `UPDATE`、永久事件 ID、关联 Tracker 条目链接、对应 Timeline 日期与原始来源。来源编号是事件内局部编号，引用时写清事件 ID，例如 `KA-001 / S1`。
- NEW：报告期首次入库的独立事件；保留实际发生日期，迟发现的旧事不能描述为本月发生。日报候选先查 Active / Closed 去重、满足入库条件后再分配正式 ID。
- UPDATE：已有事件在报告期新增事实、证据、范围、进度或反证；沿用 ID，写“此前 → 本月新增 → 判断影响”。关闭和重开也是原事件的 UPDATE。
- 同一事件本月有多次更新时合并叙述并列出关键 Timeline 日期，不按新闻篇数计数；本月 NEW 后又更新可合写“NEW，含月内进展”。DUPLICATE 不作为新进展，COMMENTARY 明确观点属性。
- 仅作为背景引用的事件标“背景”，不强制列为 NEW / UPDATE。每个实际纳入月报的事件（含 Closed 和背景引用）在 Monthly Review 追加该报告月份链接，形成双向追溯。

## 月结规则

1. 读取最新远端、确认报告窗口和输入覆盖，留存输入 Tracker 提交链接；检查 Active / Closed，补齐应入库的 NEW 及原事件 UPDATE，不覆盖已有证据。
2. 按固定结构形成月报，分别写事实、推测、待验证假设；复盘上月提出的本月 Watchlist。未解决问题延续到下月或写清停止跟踪理由，不因无消息就认定结束。
3. 按证据复核 Current Competitive View。将旧判断、新判断（或维持）、原因和支撑 ID 写在月报相应章节；Tracker 仅保留简短当前判断，并更新 Last Reviewed 为实际复核日期。重大 P0 已触发周中调整的，月结时一并回溯。
4. 将 Next Month Watchlist 同步至 Tracker，替换为目标月份。旧清单由历史月报保存；如初始化清单未存于月报，先在本期复盘中保留其内容与结果，避免丢失。
5. 给实际纳入月报的 Active / Closed 事件追加 Monthly Review 链接，保留旧月份、ID、Timeline 和 Sources；仅回填引用不刷新事件 Last Updated。结束事件按 Tracker 规则关闭并保留完整历史。
6. 检查月份、事件 ID、来源链接、双向引用及覆盖缺口；提交前再次读取远端，避免覆盖并发修改。尽量将月报与 Tracker 同步修改放在同一次提交；完成后读取远端核对并报告提交链接。
7. 已月结报告保留为历史快照。后续事实更正注明修订日期、原因及影响，不静默改写旧判断；新月份进展写入新月报与原事件 Timeline。

没有输入或证据不足时，可保留注明缺口的初稿；不得宣称已完成完整月度复核，也不提前给事件登记不存在的月报。月报的判断更新频率为月度；周五维护以事件证据和状态为主，只有重大 P0 的新增证据改变整体判断时才例外周中调整。
